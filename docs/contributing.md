# افزودن مستند جدید

راهنمای اضافه کردن صفحه به این سایت.

---

## ساختار ریپو

```
docs-repo/
├── Dockerfile          ← ایمیج nginx — دست نزن
├── index.html          ← تنظیمات docsify — به‌ندرت لازم است
├── _sidebar.md         ← منوی ناوبری  ▸ اینجا را ویرایش کن
└── docs/
    ├── README.md       ← صفحه‌ی خانه
    ├── home-server.md
    ├── contributing.md
    └── ...             ▸ فایل جدید اینجا
```

## سه قدم

### ۱. فایل مارک‌داون را بساز

```bash
touch docs/deploy-guide.md
```

**قواعد نام‌گذاری:**

| قاعده                        | مثال                                       |
| ---------------------------- | ------------------------------------------ |
| حروف کوچک انگلیسی            | `backup-strategy.md` ✅                    |
| جداکننده خط تیره، نه زیرخط   | `my-doc.md` ✅ &nbsp;&nbsp; `my_doc.md` ❌ |
| بدون فاصله و بدون حروف فارسی | `راهنما.md` ❌                             |

> نام فایل مستقیماً در آدرس ظاهر می‌شود، پس تغییر دادنش بعداً لینک‌های قبلی را می‌شکند. از اول درست انتخابش کن.

### ۲. لینک را به سایدبار اضافه کن

فایل `_sidebar.md` را باز کن و یک خط اضافه کن:

```markdown
- [خانه](/README.md)
- [راه‌اندازی سرور خانگی](/home-server.md)
- [راهنمای دیپلوی](/deploy-guide.md)
```

**دسته‌بندی** با تودرتو کردن انجام می‌شود:

```markdown
- [خانه](/README.md)

- زیرساخت
  - [راه‌اندازی سرور](/home-server.md)
  - [بکاپ](/backup.md)

- توسعه
  - [راهنمای دیپلوی](/deploy-guide.md)
```

> مسیرها با `/` شروع می‌شوند و پسوند `.md` دارند. این مسیر نسبت به ریشه‌ی سایت است، نه نسبت به فایل فعلی.

### ۳. push بزن

```bash
git add .
git commit -m "docs: add deploy guide"
git push
```

اگر `Auto Deploy` روشن باشد، Dokploy ظرف یکی دو دقیقه بیلد و منتشر می‌کند. در غیر این صورت، در پنل دستی `Deploy` بزن.

**آدرس نهایی:**

```
https://<host>/doc/#/deploy-guide
```

## قواعد نگارش

### عنوان صفحه

هر فایل باید دقیقاً **یک** عنوان سطح یک داشته باشد، در خط اول:

```markdown
# راهنمای دیپلوی

متن...
```

عناوین `##` و `###` به‌طور خودکار در سایدبار زیر همان صفحه ظاهر می‌شوند.

### کد

همیشه زبان را مشخص کن تا رنگ‌آمیزی درست کار کند:

````markdown
```bash
sudo systemctl restart nginx
```
````

زبان‌های فعال: `bash`, `yaml`, `docker`, `nginx`, `json`, `js`, `html`

### هشدارها

```markdown
> ⚠️ این دستور غیرقابل بازگشت است.

> 💡 نکته‌ی جانبی که دانستنش مفید است.
```

### لینک بین صفحات

```markdown
جزئیات در [راه‌اندازی سرور](/home-server.md) آمده است.
```

لینک به بخش خاصی از صفحه‌ی دیگر:

```markdown
[بخش عیب‌یابی](/home-server.md#عیبیابی)
```

> در انکر عناوین فارسی، فاصله‌ها به `-` تبدیل می‌شوند و نویسه‌های نامرئی مثل نیم‌فاصله حذف. اگر لینک کار نکرد، آدرس را از نوار مرورگر بعد از کلیک روی عنوان کپی کن.

### تصویر

فایل را در `docs/assets/` بگذار:

```markdown
![توضیح تصویر](assets/diagram.png)
```

مسیر تصاویر **نسبی** است (بدون `/` ابتدایی) — برخلاف لینک صفحات.

## تست محلی قبل از push

اگر Node داری:

```bash
npx docsify-cli serve .
```

روی `http://localhost:3000` باز می‌شود. برای تست تغییرات سایدبار و لینک‌ها قبل از دیپلوی مفید است.

## عیب‌یابی

| مشکل                 | علت محتمل                                                |
| -------------------- | -------------------------------------------------------- |
| صفحه ۴۰۴ می‌دهد      | فایل در `docs/` نیست، یا نامش با لینک سایدبار فرق دارد   |
| سایدبار آپدیت نشده   | کش مرورگر — `Ctrl+Shift+R`                               |
| تغییرات دیده نمی‌شود | دیپلوی انجام نشده — تب `Deployments` در Dokploy را چک کن |
| تصویر لود نمی‌شود    | مسیر با `/` شروع شده؛ باید نسبی باشد                     |
| کد رنگی نیست         | زبان بعد از ``` مشخص نشده                                |

**بررسی وضعیت دیپلوی:**

```bash
sudo docker ps --format "table {{.Names}}\t{{.Status}}"
```

## نکته‌ی امنیتی

این سایت داخل tailnet منتشر شده، ولی **همه‌ی اعضای tailnet به آن دسترسی دارند**.

قبل از نوشتن، این‌ها را ننویس:

- رمز عبور، توکن، کلید API
- محتوای فایل‌های `.env`
- کلید خصوصی SSH یا اعتبارنامه‌ی تونل

اگر لازم است به مقداری اشاره کنی، placeholder بگذار:

```bash
export API_KEY="<YOUR_API_KEY>"
```
